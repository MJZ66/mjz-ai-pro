# MJZ AI Pro — 配置与安全说明

## 1. 配置文件

| 文件 | 是否提交 Git | 说明 |
|------|----------------|------|
| `.env.example` | ✅ 是 | 模板，**值为空** |
| `.env` | ❌ 否 | 本地真实 Key，已在 `.gitignore` |
| `data/vector_store/` | ❌ 否 | ChromaDB 本地数据 |

复制模板：

```bash
copy .env.example .env
```

## 2. 环境变量详解

### 通义千问（推荐用于 RAG 向量）

```env
DASHSCOPE_API_KEY=你的通义Key
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
DASHSCOPE_MODEL=qwen-plus

EMBEDDING_MODEL=text-embedding-v3
EMBEDDING_API_KEY=你的通义Key
EMBEDDING_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
```

### DeepSeek（仅对话）

```env
DEEPSEEK_API_KEY=你的DeepSeekKey
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
```

### 统一兼容写法（可选）

```env
OPENAI_API_KEY=你的通义Key
OPENAI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
MODEL_NAME=qwen-plus
```

## 3. 侧边栏与 `.env` 优先级

- 侧边栏 **API Key 留空** → 自动读取 `代码文件/.env`（与 `app.py` 同目录）。
- 侧边栏 **填写 Key** → 覆盖 `.env` 中对话 Key。
- **DeepSeek 模式**：仅读取 `DEEPSEEK_API_KEY`，不会误用通义 Key 调 DeepSeek（避免 401）。

## 4. 厂商与能力对照

|------|----------|----------|
| 多轮对话 | ✅ | ✅ |
| RAG 向量化 | ✅ | ❌（需通义 Key） |

## 5. 提交前自检（防止泄露）

在仓库根目录执行：

```bash
# 确认 .env 未被跟踪
git check-ignore -v .env

# 搜索误提交的 Key（应无真实 sk- 长串）
git grep -E "sk-[a-zA-Z0-9]{20,}" || echo "未发现硬编码 Key"
```

**切勿提交：**

- `.env`、`.streamlit/secrets.toml`
- 含真实 Key 的截图、日志、聊天记录导出
- `data/` 下向量库（可能含文档原文）

## 6. Key 泄露后的处理

1. 在阿里云 DashScope / DeepSeek 控制台**作废并重新生成** Key。
2. 更新本地 `.env`，不要写进 Issue / PR。
3. 若曾误 push，使用 `git filter-repo` 或 GitHub Secret scanning 指引清理历史。
